现在这块“宿舍状态”的逻辑，实际包含 4 层。

1. 数据来源
   后端低碳总览接口先算出每个宿舍的基础指标，再返回给前端，核心字段是：

- `carbonScore`
- `totalFee`
- `totalCarbon`
- `residentCount`
- `dataUpdatedAt`
- `currentPeriodParticipating`

前端类型在 [dashboard.ts](D:/study/system/low-carbon-dormitory/low-carbon-dormitory-vue/src/api/modules/dashboard.ts:77)，后端组装在 [LowCarbonDashboardService.java](D:/study/system/low-carbon-dormitory/low-carbon-dormitory-spring/src/main/java/com/example/lowcarbondormitory/service/dashboard/LowCarbonDashboardService.java:207)。

2. 状态判定
   前端用这 3 个值做状态分类，逻辑在 [dashboard-status.ts](D:/study/system/low-carbon-dormitory/low-carbon-dormitory-vue/src/utils/dashboard-status.ts:17)：

- `score < 0` 或 `totalFee >= 10` 或 `totalCarbon >= 15`
  结果：`异常`
- 否则，如果 `score < 10` 或 `totalFee >= 0.8` 或 `totalCarbon >= 7`
  结果：`预警`
- 否则，如果 `score >= 55` 且 `totalFee <= 0.3` 且 `totalCarbon <= 4.5`
  结果：`优秀`
- 其他情况
  结果：`良好`

这是一套优先级判断，不是打分叠加。
也就是先判“异常”，再判“预警”，再判“优秀”，最后才是“良好”。

3. 页面展示
   总览页把每个宿舍先跑一遍 `getDormStatus(dorm)`，再生成：

- `statusKey`
- `statusText`

位置在 [low-carbon-dashboard-overview.vue](D:/study/system/low-carbon-dormitory/low-carbon-dormitory-vue/src/router/student-router/dashboard/low-carbon-dashboard-overview.vue:196)。

然后页面右上角的标签就是：

- `excellent -> 优秀`
- `good -> 良好`
- `warning -> 预警`
- `abnormal -> 异常`

4. 和业务规则的关系
   这里要注意，当前“宿舍状态”逻辑和“低碳积分规则”不是一套东西。

现有后台低碳规则能配置的是：

- `baseScore`
- `electricCarbonFactor`
- `waterCarbonFactor`
- `carbonPenaltyFactor`
- 荣誉规则等

定义在：

- [low-carbon-rule.ts](D:/study/system/low-carbon-dormitory/low-carbon-dormitory-vue/src/api/modules/low-carbon-rule.ts:4)
- [LowCarbonRuleConfigRequest.java](D:/study/system/low-carbon-dormitory/low-carbon-dormitory-spring/src/main/java/com/example/lowcarbondormitory/dto/request/LowCarbonRuleConfigRequest.java:24)

但“异常/预警/优秀/良好”的阈值目前不在后台规则里，而是前端单独写死的。

所以完整逻辑链其实是：

- 后端先算费用、碳排、积分
- 前端再用固定阈值做状态分类
- 页面显示“异常/预警/良好/优秀”

如果你问“以后做成动态，逻辑要包含什么”，通常会包含这些字段：

- 异常费阈值
- 异常碳阈值
- 异常积分阈值
- 预警费阈值
- 预警碳阈值
- 预警积分阈值
- 优秀最低积分
- 优秀最高费用
- 优秀最高碳排
- 状态优先级规则
